# Протокол надёжной доставки

Заголовок UDP-пакета занимает 8 байт: `type uint8`, `sequence uint16`, `payloadSize uint16`, `protocolVersion uint16`, `requiresAck uint8`. Все многобайтовые числа передаются в big-endian. Типы пакетов: `PING=1`, `PONG=2`, `MOVEMENT=3`, `SHOOT=4`, `ACK=5`. Полезная нагрузка ACK содержит `acknowledgedSequence uint16`.

`SHOOT` отправляется с `requiresAck=1`, потому что потеря выстрела меняет результат игры. `MOVEMENT` не требует ACK: запоздалая старая координата уже не нужна, её заменяет следующая позиция.

Клиент хранит неподтверждённый пакет целиком, время первой и последней отправки и число попыток. По истечении RTO он повторяет те же байты и тот же sequence. После максимального числа попыток команда считается недоставленной. Неизвестные, повторные и запоздалые ACK игнорируются.

Сервер отвечает ACK на каждую принятую надёжную команду. Окно последних sequence защищает игровой эффект от повторного выполнения: дубликат снова подтверждается, но не обрабатывается второй раз.

RTO вычисляется по SRTT и RTTVAR: первая выборка задаёт `SRTT=RTT`, `RTTVAR=RTT/2`; далее используются коэффициенты 0.125 и 0.25. `RTO = clamp(SRTT + 4*RTTVAR, 100 мс, 3000 мс)`. По алгоритму Карна RTT команды после повторной отправки не используется.
